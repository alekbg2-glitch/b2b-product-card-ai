## 📌 2. Архитектура и принятые решения

### Архитектурный стек:
- **Backend:** Python 3.12, **FastAPI** (асинхронная архитектура, строгая валидация схем через **Pydantic v2**).
- **LLM Provider:** Универсальный клиент через `httpx.AsyncClient`, совместимый с любым OpenAI-совместимым API (OpenAI, DeepSeek, Google Gemini, Ollama). Ключи изолированы в переменных окружения.
- **Frontend / UI:** Адаптивный мобильный интерфейс на **Bootstrap 5.3 + Vanilla JS** с полным разделением логики: HTML-шаблоны в `/app/templates/`, стили в `/static/css/styles.css`, клиентская логика в `/static/js/main.js`.
- **CLI-интерфейс:** Полноценный консольный режим (`cli.py`) для пакетной генерации.

### Ключевые инженерные решения и Guardrails:
1. **Защита от галлюцинаций (Zero-Hallucination Policy):**
   - Все технические параметры (диапазоны, резьбы, класс точности, напряжения) извлекаются **исключительно** из входных данных.
   - Если характеристика отсутствует, модель обязана вернуть статус `«данных нет»`.
2. **Точный контроль SEO-лимитов:**
   - **SEO Title:** строго до **70 символов** включительно (в тестах: 53–58 знаков).
   - **SEO Description:** профессиональный B2B-текст объёмом строго **800–1200 символов** без «воды». В интерфейсе выведены динамические счетчики знаков.
3. **Детектор недостающих данных для контент-менеджера:**
   - Модель анализирует входные данные с точки зрения инженера КИПиА. Если не указаны критичные параметры (степень защиты IP, межповерочный интервал, температура среды, габариты или резьба), формируется блок замечаний `missing_data_warnings`.
4. **Коммерческий блок отдела продаж:**
   - Целевая аудитория, решаемые прибором задачи на объекте и конкурентные преимущества.

## 🧪 4. Автоматическое тестирование

В проект встроен скрипт валидации, тестирующий соответствие всем пунктам ТЗ:
```bash
python3 run_tests.py
```
Проверяет:
- Лимит SEO Title (<= 70 символов).
- Диапазон длины SEO Description (800–1200 знаков).
- Ровно 3–5 поисковых запросов.
- Отсутствие выдуманных характеристик.
- Срабатывание детектора замечаний для контент-менеджера.

## 🛠 5. Ограничения решения и вектор развития (Production Roadmap)

1. **RAG / Интеграция с базой ГОСТ и технической документацией:**
   Подключение векторной БД (Chroma/Qdrant) с PDF-паспортами приборов для автоматического извлечения схем подключения и сертификатов.
2. **Интеграция с ERP/CMS (1С, Bitrix, OpenCart):**
   Прямая пакетная выгрузка сгенерированных карточек по REST API в каталог интернет-магазина.
3. **Human-in-the-Loop:**
   Инструмент одобрения/правки карточек контент-менеджером для накопления Few-Shot примеров и дообучения локальной модели.
